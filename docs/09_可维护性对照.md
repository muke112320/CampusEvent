> 口径：源码仅统计 `app/**/*.py`（含 docstring 与类型注解，不含测试与文档）；行数按文件逐行累加；差异用 `git diff --numstat baseline-v1..change-v2`；测试数由 pytest 收集结果与测试函数清单核对。
> 复现命令：
>
> ```powershell
> git diff --stat baseline-v1..change-v2
> git diff --numstat baseline-v1..change-v2 -- app
> .\.venv\Scripts\python.exe -m pytest -q
> ```

## 5. 结论

1. **策略模式收益成立**：CR-01 引入年级限定报名，只新增 1 个策略类并在注册表登记 1 行；核心报名服务零改动，公共校验与容量逻辑完全复用。
2. **观察者模式收益成立**：CR-02 新增 MockEmailSender 与邮件台账，站内订阅者与业务服务零修改；失败隔离与幂等由订阅者模板和唯一约束保证。
3. **模式成本同样真实**：源码增加 281 行、新类 4 个、删除类 3 个，调用链更长；对规则稳定的系统未必划算。
4. **真正需要人工判断的是边界**：年级默认值迁移、CHECK 约束重建、邮件失败不回滚、同一事件不重复发送——这些不是模式自动保证的，而是由设计决策与测试固定下来的。
